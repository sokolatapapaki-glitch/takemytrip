# Mobile Layout & Navbar Behavior Updates

## 1. Full-Width Mobile Layout

### Goal
On mobile devices, the navigation and all major page sections should span the full width of the viewport.

### Requirements
- Remove any unnecessary horizontal padding, margins, max-width constraints, or container limitations that prevent sections from using the full screen width.
- Apply this to:
  - Navigation bar
  - Hero section
  - Content sections
  - Footer (if applicable)
- Desktop and tablet layouts should remain unchanged unless required for consistency.

### Acceptance Criteria
- On screens below the mobile breakpoint, content stretches edge-to-edge.
- No visible side gutters created by layout containers.
- No horizontal scrolling is introduced.

---

## 2. Remove Homepage Background Wrapper on Mobile

### Goal
The homepage's background wrapper/container should not be visible on mobile devices.

### Requirements
- Identify the component responsible for the decorative background wrapper behind the homepage content.
- Disable or hide this wrapper on mobile screens only.
- Desktop and tablet experiences should remain unchanged.

### Acceptance Criteria
- Mobile users see homepage content directly without the background wrapper effect.
- Desktop users continue seeing the existing background wrapper.

---

## 3. Transparent Desktop Navbar at Top of Page

### Goal
Create a modern navbar behavior on desktop screens.

### Initial State (Top of Page)
When the page first loads and the user has not scrolled:

- Navbar background should be transparent.
- Navbar should appear to float over the hero section.
- Navigation text/icons/logo should use colors that remain clearly visible against the hero background.

### Scrolled State
After the user scrolls down:

- Navbar should smoothly transition to its current solid background color.
- Existing navbar styling should be restored.
- Text colors should transition appropriately if needed.

### Requirements
- Apply this behavior only on desktop screens.
- Mobile navbar behavior should remain unchanged.
- Use a smooth transition for:
  - Background color
  - Border (if present)
  - Shadow (if present)
  - Text colors

### Suggested Implementation
- Track scroll position.
- Add a `scrolled` state when the user scrolls beyond a small threshold (e.g. 20–50px).
- Conditionally apply navbar classes/styles.

### Acceptance Criteria
- At page top: transparent navbar.
- After scrolling: navbar gains its normal background color.
- Transition feels smooth and polished.
- Desktop only.
- Mobile behavior remains exactly as it is now.

---

## Technical Notes

### Do Not Change
- Existing routing.
- Navigation functionality.
- Desktop layout widths (except navbar transparency behavior).
- Existing animations unrelated to these tasks.

### Ensure
- No layout shifts occur during scrolling.
- Accessibility and readability remain intact.
- Responsive breakpoints remain consistent with the current design system.
